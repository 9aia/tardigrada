Decisions ​

ADR-lite: decision → alternatives → consequence.

File backend only in v1 ​

Decision: the only identity backend is file — an identity.txt-style keyfile at the resolved path.

Alternatives: ship a keyring backend now; a daemon or remote identity service.

Consequence: headless, CI-friendly, zero moving parts — but the key sits on disk (mitigated by 0600 + the load-time permission warning). The keyring impl exists upstream (cuora-identity-keyring) yet hardcodes the "cuora" service name; a tardigrada backend needs upstream parameterization or a thin local impl. Tracked in project/.

export/import over config coupling ​

Decision: cuora interop is "point both tools at the same keyfile" or "move the keyfile" — no cuora-aware verbs, no shared config discovery.

Alternatives: tardigrada reads/writes cuora's config; a tardigrada cuora subcommand family.

Consequence: tardigrada manages generic identities — it never learns what vaults, cuora:// refs, or envs are. The integration surface stays one file and two env vars; either tool can be swapped without the other noticing.

Payload bin, not a driver shim ​

Decision: the tardigrada command ships as a tamias type: files pack whose bins[].payload is the compiled binary staged by scripts/pack.sh — a real binary on PATH.

Alternatives: the org's usual bins[] shim → tamias-driver-* → engine-lib passthrough (cuora/myco shape); a driver crate.

Consequence: no shim→driver→engine indirection for a tool this size — one fewer crate, one fewer process, cargo install --path and tamias install both deploy the same artifact. The cost is a per-triple build artifact (tools/bin/<triple>/, gitignored) instead of a portable shim.

init never clobbers; import overwrites deliberately ​

Decision: init is idempotent-safe (second run reports the existing recipient); import replaces whatever identity is configured, with no undo.

Alternatives: init --force; import to a staging path.

Consequence: the dangerous verb is the explicit one — adopting an existing key is a deliberate act, and pointing import at the wrong file is on the operator (SECURITY.md scope note). export refuses bare-stdout under --json for the same reason: a secret inside a JSON envelope invites accidental logging.
